# 1. KAMP 50개 데이터셋 개요 및 정리

KAMP(인공지능 제조 플랫폼)에 등재된 무료 제조 AI 데이터셋 50개를 실제로 열어서(zip 내부 컬럼 구조, 공식 가이드북) 정리한 표입니다. 대회에서 어떤 데이터셋이 나오더라도 빠르게 "이게 어떤 유형인지" 감을 잡을 수 있도록, 아래 정보를 모든 데이터셋에 대해 통일된 기준으로 정리했습니다.

### 표를 읽는 법

| 컬럼 | 의미 |
|---|---|
| 산업/업종 | 어느 제조업종 데이터인지 |
| 제조공정 | 그 업종 안에서 구체적으로 어떤 공정 단계인지 |
| 주요 설비 | 데이터를 만들어낸 장비 |
| 데이터 형태 | 파일 종류, 한 행의 단위 |
| 해결하려는 제조 문제 | 이 데이터셋이 실제로 다루는 이슈 |
| 분석 유형 | 품질예측 / 품질분류 / 불량탐지 / 설비이상탐지 / 예지보전 / 공정분석 / 공정최적화 / 이미지검사 / 시계열분석 / 기타 |
| 핵심 제조 키워드 | 검색·복습용 키워드 |
| 우선순위 | 아래 참고 |

**우선순위(A/B/C)** — 데이터셋 구조·라벨 방식·문제정의가 50개 중 같은 패턴을 대표하는 정도로 매겼습니다.
- **A**: 특정 패턴(예: 라벨 없는 데이터 다루기, 이미지 객체탐지 등)을 가장 전형적으로 보여주는 데이터셋
- **B**: A와 같은 패턴을 다른 설비·공정에 적용했거나 이미 가공된 형태
- **C**: 새로 배울 패턴이 없거나(다른 데이터셋과 원본이 사실상 동일), 온도·진동 같은 제조 현상이 아니라 발주량·인력 배치 같은 경영/물류 데이터

# 2. 데이터셋별 제조 도메인 조사 자료

KAMP 50개 데이터셋을 실제로 열어(zip 내부 컬럼, 공식 가이드북) 정리한 제조 도메인 배경지식입니다. **[사실]** = 데이터/공식 문서에서 직접 확인된 내용, **[추론]** = 일반적인 제조 지식으로 유추한 내용입니다.

---

### 1. 큰 그림: 제조 데이터가 만들어지는 6단계

업종은 달라도 데이터가 만들어지는 흐름은 항상 같습니다.

```
제조산업 → 제조공정 → 설비 → 공정에서 발생하는 현상 → 센서/검사 데이터 → 품질/설비 문제 → 데이터로 확인 가능한 문제
```

즉 "제조산업(예: 식품가공)" 안에 "제조공정(예: 용해공정)"이 있고, 그 공정을 "설비(예: 용해탱크)"가 수행하며, 그 과정에서 "현상(예: 온도 변화)"이 생기고, 이를 "센서 데이터(온도값)"로 기록하며, 그 결과가 "품질/설비 문제(불량, 고장)"로 나타나고, 우리는 그 데이터로 "확인 가능한 문제(불량 예측, 고장 예측 등)"를 풉니다.

> KAMP 데이터셋은 "원본 그대로"가 아니라 이미 한 번 정제된 "분석용 테이블"입니다. 실제 현장에서는 PLC·MES·센서 로거가 각각 따로 데이터를 쌓고, 이를 합치는 전처리가 별도로 필요합니다.

---

### 2. 공정군별 정리

50개는 크게 9개 공정군으로 묶입니다. 같은 공정군은 설비·변수·불량 개념이 거의 동일해서, 하나를 깊게 이해하면 나머지는 빠르게 이해됩니다.

#### 절삭/정밀가공군 (CNC, 정밀가공 품질보증/자원최적화)
- CNC(Computer Numerical Control)는 절삭가공을 컴퓨터로 자동 제어하는 방식. 핵심 부품은 **spindle**(공구를 고속 회전시키는 축)과 X/Y/Z축 서보모터.
- **[사실]** CNC 데이터는 "지시값(Set)"과 "실제값(Actual)"을 같이 기록 — 기계가 지시대로 움직였는지, 그때 얼마나 힘(전류)이 들었는지를 함께 봄.
- **[사실]** `feedrate`(이송속도), `clamp_pressure`(고정압력)가 조건으로 기록되고, 결과는 `tool_condition`(공구마모)과 `passed_visual_inspection`(육안검사 통과)로 구분 — 설비 문제(공구마모)와 품질 문제(불량)가 별도 라벨로 존재.
- 핵심 용어: **spindle**, **feed rate**, **공구 마모**

#### 성형(사출·프레스·소성가공)군
- 원재료에 열·압력·속도를 가해 금형 안에서 형태를 만드는 공정. 사출성형(수지를 금형에 주입)/프레스(판재를 눌러 찍음)/소성가공(압출·단조 등 포함 상위개념).
- **[사실]** 사출성형 데이터는 `Injection_Time, Filling_Time, Cycle_Time, Max_Screw_RPM` 등 시간·위치·속도로 세분화되어 기록되고, `PassOrFail` + `Reason`(불량 사유 텍스트)까지 라벨링됨.
- 핵심 용어: **금형(mold)**, **cycle time**(제품 1개를 만드는 데 걸리는 시간, 이 공정군의 핵심 KPI), **클램핑**

#### 용접군
- 두 금속을 열·압력·전류로 붙이는 접합 공정. 스팟용접(점 단위로 짧게 큰 전류를 흘림)이 대표적.
- **[사실]** `용접 가압력, 전류, 전압, 통전시간`이 핵심 변수. 라벨 없이 "비지도 이상치 탐지"로 접근하는 경우가 많음(정상 범위를 벗어난 것 = 불량 후보).
- **[추론]** 전류가 부족하면 미용착, 과하면 번아웃/스패터 가능성.
- 핵심 용어: **스팟용접**, **통전시간**, **미용착**

#### 주조군 (다이캐스팅)
- 금속을 녹여 금형에 고압으로 빠르게 주입해 굳히는 다이캐스팅.
- **[사실]** 컬럼 헤더가 `Process`(공정조건: Velocity, Pressure 등) → `Sensor` → `Defects`(불량유형)로 그룹화되어 있어 "공정조건→현상→불량"의 흐름을 그대로 보여줌.
- **[사실]** "가생산(warm-up run)": 설비가 정상 온도 도달 전 예열 중 나오는, 처음부터 폐기 전제인 제품. **불량과는 다른 개념** — 불량은 몰라서 생기는 문제, 가생산은 알고도 감수하는 예열 비용.
- 핵심 용어: **다이캐스팅**, **shot(사출 1타 = 제품 1개)**, **가생산**

#### 열처리군
- 금속을 고온 가열 후 급랭(담금질)시켜 강도·경도를 바꾸는 공정.
- **[사실]** 소입로·건조로·염욕조(salt bath)로 구성, 로가 여러 구간(Zone)으로 나뉘어 각기 온도 제어됨.
- **[사실]** 열처리는 2시간 이상 걸리는 연속공정이라 불량이 나와도 즉시 알기 어렵고 설비를 세우기도 어려움 — 그래서 "사전 예측(예지보전)"이 특히 중요한 공정으로 소개됨.
- 핵심 용어: **담금질**, **소입로**, **Carbon Potential(CP)**, **염욕**, **Zone**

#### 표면처리군 (전해탈지 → 도금 → 크로메이트)
- 금속 표면에 방청·미관·전기적 성질을 부여하는 화학처리 라인.
- **[사실]** 여러 데이터셋이 같은 사업장·비슷한 시기의 센서 로그(`kemp-abh-sensor-*.csv`)를 공정 단계별로 나눠 제공. 각 단계마다 측정 변수가 다름 — 전해탈지(pH,Temp,Current) / 도금(+Voltage) / 크로메이트(pH,Temp,Voltage).
- **[사실]** 불량 Lot 목록(`Error Lot list.csv`)이 센서 로그와 별도 파일로 존재 — 날짜/Lot 기준 결합이 필요.
- 핵심 용어: **전해탈지**, **도금(전기도금)**, **크로메이트**, **PLC**, **Lot**

#### 식품·화학 연속공정군 (용해 → 살균 → 건조)
- **[사실]** 분말·액상 원재료를 용해(녹이고 섞기) → 살균(가열 미생물 제거) → 건조(재분말화) 순서로 처리.
- **[사실]** 같은 용해탱크 설비라도 품질 라벨이 있는 데이터(`INSP`)와, 라벨 없이 진동값만 있는 설비 데이터가 별도로 존재 — "품질 데이터"와 "설비 데이터"가 같은 라인에서도 다름을 보여주는 사례.
- 핵심 용어: **SOP(표준운영절차)**, **교반**, **Lot**

#### 전자부품·배터리 조립/검사군
- 배터리 셀→모듈→팩 조립, 레이저 용접, 충·방전 시험.
- **[사실]** 배터리팩 시험 데이터는 모듈(M01~M16)별 셀 전압을 176개 컬럼으로 개별 기록 — 완제품 하나가 다수 하위부품의 집합이라는 걸 컬럼 수로 확인 가능.
- **[사실]** OK/NG가 아예 폴더로 분리 제공되는 경우가 많아 지도학습 라벨이 깨끗함.
- 핵심 용어: **셀/모듈/팩**, **충방전**, **AAS**(Industry 4.0 설비 메타데이터 표준, `.aasx` 파일)

#### 이미지·오디오 검사군
- 이미지 전체 1장에 라벨 1개("분류") vs 이미지 안 특정 위치를 찾는 라벨("객체탐지")로 문제 성격이 갈림.
- **[사실]** 안전관리 데이터는 CCTV 프레임에 사람 위치를 bounding box로 표시(객체탐지). Scene-Text는 저울 LED 숫자 하나하나를 문자 단위로 검출+인식(더 세밀한 탐지). 머신비전은 이미지 1장=양/불 라벨 1개(순수 분류).
- 오디오(음향기기 품질검사)는 소리를 파형(시계열)으로 다룸 — 50개 중 유일한 오디오 사례.
- 핵심 용어: **분류 vs 객체탐지**, **bounding box**, **YOLO**

### 3. 센서 변수 공통 정리

| 변수 | 무엇을 재는가 | 왜 중요한가 |
|---|---|---|
| 온도(Temp) | 설비/재료의 열 상태 | 열처리(강도 결정), 표면처리(반응속도), 사출성형(수지 유동성) 등 거의 모든 공정에서 등장 |
| 압력(Pressure) | 유압/공압/사출압 | 부족하면 성형 불량, 과하면 설비 부담 가능성 |
| 속도(Velocity) | 이송·회전·주입 속도 | 너무 빠르면 품질 불안정, 느리면 생산성 저하 |
| 전류(Current) | 모터/전기설비 전기량 | 용접 접합 에너지, 전기도금 반응속도, 모터 부하 이상 신호 |
| 전압(Voltage) | 전기설비 전위차 | 전류와 함께 관찰, 배터리는 셀 상태 자체를 나타내는 핵심 지표 |
| 진동(Vibration) | 설비의 미세한 흔들림 | 회전체·모터·베어링의 물리적 상태를 가장 직접적으로 보여줌 |
| pH | 산성/알칼리성 | 표면처리 화학조의 농도·반응성 지표 |
| cycle time | 제품 1개(1shot)당 소요시간 | 생산성 지표이자 평소보다 길어지면 설비 이상 신호 가능성 |

**패턴**: 대부분의 데이터가 "목표값(Set/지시)"과 "실제값(Actual/진행)"을 쌍으로 기록합니다. 이 둘의 **편차** 자체가 품질에 영향을 주는 파생 변수일 수 있습니다.

### 4. 품질과 불량

- **Lot**: 같은 조건으로 함께 처리된 제품 묶음(표면처리·염색 등 배치 공정에서 흔함)
- **Shot**: 사출성형·다이캐스팅처럼 한 번 누를 때마다 제품 하나가 나오는 공정의 동작 단위
- **불균형 데이터**: 제조 현장은 정상 제품이 압도적으로 많고 불량은 드묾(회전기계 데이터셋 공식 설명: "정상 유형이 90% 이상"). 그래서 일부러 고장을 낸 실험장치(testbed)로 데이터를 모으거나, 정상 데이터만으로 학습하는 비지도 이상치탐지 방식을 쓰는 경우가 많음.
- **공정 데이터 / 품질 데이터 / 설비 데이터**는 같은 라인에서도 성격이 다를 수 있음:
  - 품질 데이터: 최종 제품 양/불량 라벨 (예: `PassOrFail`)
  - 설비 데이터: 설비 자체 물리 상태, 제품 라벨 없을 수 있음 (예: 진동값만)
  - 공정(운영) 데이터: 위 둘의 원인이 되는 조건값 자체

---

### 5. 설비 이상과 예지보전

- **이상탐지**: 지금 이 순간의 데이터가 평소와 다른가?
- **예지보전(PdM)**: 지금 추세로 가면 앞으로 고장/비정상이 될 것인가? (이상탐지보다 한 단계 더 나아간 "사전 조치" 개념)
- **오토인코더(Autoencoder)**: 정상 데이터만으로 학습해 입력을 복원하고, 복원이 잘 안 되는(재구성 오차가 큰) 경우를 이상으로 판단 — 불량 샘플을 충분히 모으기 어려운 제조 현장에서 자주 쓰이는 이유.
- **Decision Tree/XGBoost 계열**: 정상/불량을 가르는 기준을 사람이 해석하기 쉬운 형태로 찾아낼 때 자주 사용.

---

### 6. 제조데이터의 대표적인 형태

1. **연속 시계열 센서 로그** — 한 행 = 한 시점 (가장 많음)
2. **배치(Lot/Shot) 단위 정형 데이터** — 한 행 = 제품/로트 하나, 시계열을 통계 요약해서 만드는 경우 많음
3. **파형(waveform) 시계열** — 컬럼 자체가 시간축, 한 행 = 사건 하나의 전체 파형
4. **이미지** — 분류용(1장=라벨1개) / 탐지용(1장=여러 위치+라벨)
5. **오디오(wav)**
6. **텍스트/공급망 테이블** — 발주량, 생산계획 등 제조 현상이 아닌 비즈니스 활동 기록

### 7. 분석 문제 유형 10가지

| 유형 | 정의 | 전형적 입출력 |
|---|---|---|
| 품질 예측 | 공정조건→품질 수치(연속값)를 회귀로 추정 | 공정변수 → 연속값 |
| 품질 분류 | 공정조건/제품 데이터→양품/불량 분류 | 공정변수 → 범주(OK/NG) |
| 불량 탐지 | 완성품 자체(이미지·검사값)에서 불량 유무/위치 탐지 | 이미지/검사값 → 불량 여부·위치 |
| 설비 이상탐지 | 현재 설비 상태가 정상 범위를 벗어났는지 판단 | 센서 시계열 → 정상/이상(현재) |
| 예지보전 | 앞으로 설비 문제가 생길지 미리 예측 | 센서 추세 → 향후 이상 가능성 |
| 공정 분석 | 변수 간 상관관계·영향도 탐색 | 공정변수 전체 → 변수 중요도 |
| 공정 최적화 | 불량을 줄이는 최적 조건 탐색 | 공정변수+결과 → 추천 조건값 |
| 이미지 검사 | 컴퓨터비전으로 육안검사 대체 | 이미지 → 분류/객체탐지 결과 |
| 시계열 분석 | 시간 흐름 자체가 중요한 패턴/예측 문제 | 시계열 → 미래값/패턴 |
| 기타 | 스케줄링, 자원배분 등 | 제약조건 → 최적 배치 |

# 3. 데이터 분석 프로세스

일반적인 데이터분석 프로세스(문제정의→EDA→모델링→평가)를 그대로 쓰지 않고, KAMP 50개 데이터셋에서 반복적으로 확인된 제조데이터 특성을 반영해 설계한 프로세스입니다. **특정 머신러닝 알고리즘을 지정하지 않습니다** — "무엇을 예측/분류/최적화할지"를 결정하는 것까지가 이 프로세스의 범위이고, 세부 모델 선택은 그 다음 문제입니다.

---

### 1. 왜 일반 프로세스를 그대로 안 쓰는가 — 제조데이터의 반복 특성

| # | 특성 | 확인된 근거 | 프로세스에 반영할 점 |
|---|---|---|---|
| 1 | 공정·설비를 먼저 이해해야 함 | 같은 컬럼명(`Temp` 등)도 공정마다 의미가 다름. 데이터셋 이름과 실제 분석 유형이 어긋나는 경우도 있음(예: "자원최적화"라는 이름인데 실제로는 설비 이상탐지) | 데이터를 열기 전에 공정·설비부터 확인 |
| 2 | 한 행의 단위(grain) 확인 필요 | 시점 단위 / Lot 단위 / Shot 단위 / 파형 단위가 데이터셋마다 다름. 같은 데이터셋 안에서도 파일마다 단위가 다른 경우 있음(조건표 vs 시계열) | 단위를 먼저 확정하고, 다르면 결합 키를 정함 |
| 3 | 공정/품질/설비 데이터의 성격이 다름 | 같은 라인에서도 어떤 파일은 품질 라벨이 있고 어떤 파일은 설비 진동값만 있음 | 데이터 성격 분류가 EDA보다 먼저 |
| 4 | 시간축 유무·종류가 다름 | 연속 모니터링형 vs 파형형 vs 순서 무관형(Shot 단위) | train/test 분리 방식을 시간축 종류에 맞게 결정 |
| 5 | 라벨 유무가 다름 | 라벨이 이미 있음 / 다른 파일과 결합 필요 / 아예 없음(비지도 이상치탐지로 접근) 세 갈래가 실제로 존재 | target 확정 방식을 미리 분기 |
| 6 | 결측치·이상치는 원인이 있는 경우가 많음 | 여러 센서 병합 시 수집주기 차이로 생기는 결측, 설비 정지 구간 등 | 원인을 먼저 설명하고 처리 방법을 정함 |
| 7 | 불균형 데이터가 흔함 | "정상이 90% 이상" 같은 공식 설명이 다수. 그래서 비지도 이상치탐지 접근이 많이 쓰임 | 평가 지표·접근법을 불균형 정도에 맞게 분기 |
| 8 | 공정변수-품질 관계는 "관리 가능한 구간"까지 연결해야 함 | 다수 데이터셋이 "변수 중요도 확인 → 정상 구간 역산" 방식을 취함 | 상관관계 계산에서 끝내지 않고 관리 구간 제시까지 |
| 9 | 설비 이상과 품질 이상은 원인이 다를 수 있음 | 같은 설비의 "가생산(예열)"과 "진짜 불량"은 겉보기엔 비슷해도 다른 문제 | 이상 신호가 설비 문제인지 제품 문제인지 항상 구분 |
| 10 | 결과는 현장 실행으로 연결되어야 함 | 공식 결과 서술이 "비용절감", "생산차질 방지" 같은 실행 관점으로 끝남 | 마지막 단계를 수치가 아니라 실행 문장 + 한계로 마무리 |

```
      ↓
[1] 문제정의

      · 라벨이 다른 파일에 있어 결합이           │

      · 라벨이 아예 없는가?                      │
      · 불균형 정도는?                           │
      ↓                                          ↓

      ↓                                          ↓
[4] 데이터 품질 점검 (공통)
      결측·이상치·중복 → 제거/대체 전에 "왜 생겼는가"부터 확인
      ↓
[5] EDA (기술통계, KAMP AI-PaaS/Note 활용 가능)

      ↓
[6] Feature Engineering
      원본을 분석 단위(Lot/Shot)에 맞는 요약변수·파생변수로 변환
      ※ 이 시점부터 "이 변수, 다른 공정에도 있을 법한가"를 함께 기록 (확장성 대비)
      ↓
[7] 분석 / 모델링
      [3A] 지도학습형 분석 (분류·회귀 등) / [3B] 비지도 이상탐지형 분석
      ↓

      불균형이 있었다면 정확도 단독이 아니라 그에 맞는 지표로 판단

      지금 잡은 이상/불량이 설비 문제인지, 제품 문제인지,

      ↓
[10] 제조적 해석 + 현장 적용
      통계 용어가 아니라 공정 용어로 재설명, "현장의 누가 무엇을 다르게 해야 하는가"
      ↓
[11] 확장성 정리
      6~10단계에서 메모해둔 "다른 공정·업종에도 통할까"를 취합해 정리
```

### 3. 단계별 상세 (무엇을 / 왜 / 특별히 확인할 것 / 건너뛰면 생기는 문제)

| 단계 | 무엇을 하는가 | 왜 필요한가 | 제조데이터에서 특별히 확인할 것 | 건너뛰면 생기는 문제 |
|---|---|---|---|---|
| 0. 도메인·설비 이해 | 업종·공정·설비 파악, 정상 흐름을 한 문장으로 정리 | 컬럼명이 공정마다 의미가 달라서, 모르면 해석 자체가 불가능 | 컬럼명 속 전문용어(Zone, Spindle, pH, Shot 등)를 용어사전에서 확인 | 물리적으로 말이 안 되는 상관관계를 인과관계로 착각 |
| 1. 문제정의 | 분석으로 바꾸고 싶은 현장 의사결정을 한 문장으로 | 같은 데이터도 질문에 따라 완전히 다른 분석이 됨 | 품질예측/설비상태파악/조건추천 중 어디에 가까운지 구분 | EDA 중 계속 곁길로 새어 결론 없는 분석이 됨 |
| 2. 데이터 구조·성격 파악 | 행 단위, 시간축 종류, 공정/품질/설비 성격, 라벨 유무 확정 | 이후 모든 집계·분리 방식을 결정 | 여러 파일의 단위가 다르면 조인 기준(Lot/날짜/ID)을 미리 적어둠 | 단위 착각으로 집계가 통계적으로 무의미해짐 |
| 3A/3B. 라벨 결합 또는 정상 정의 | 라벨-변수 정합성 확인 또는 정상 패턴/이상판정 기준 설계 | 라벨 없는 데이터는 "정상 정의"가 분석의 절반 | 설비 예열구간처럼 "비정상처럼 보이지만 정상"인 특수 구간 확인 | 라벨이 밀려 결합되거나, 정상 정의가 애매해 이상탐지 결과가 흔들림 |
| 4. 데이터 품질 점검 | 결측·이상치·중복의 원인 추적 | 제조 결측/이상치는 원인이 있는 신호인 경우가 많음(설비정지 등) | 원인이 분석 목적과 관련된 신호인지, 단순 노이즈인지 구분 | 중요한 신호(설비 정지 등)를 실수로 지워버림 |
| 5. Feature Engineering | 시계열 → Lot/Shot 단위 요약·파생변수 변환 | 원본 시계열은 그대로 Lot 단위 분석에 못 씀 | 목표-실제 편차, Zone 간 편차 등 공정 지식 반영 변수 우선 | 단위 불일치로 분석 불가 또는 해석 불가능한 통계값만 남음 |
| 6. 분석/모델링 | 문제정의·데이터성격에 맞는 분석 수행 | 앞 단계가 "올바른 질문에 올바른 데이터로" 분석하기 위한 준비였음 | 시간축이 있으면 시간 순서를 지켜 train/test 분리 | 앞 단계 오류가 결과에 그대로 반영되어 그럴듯하지만 틀린 결론 |
| 7. 평가 | 결과가 질문에 답이 되는지, 통계적으로 믿을만한지 확인 | 불균형 데이터는 흔한 지표가 오해를 부를 수 있음 | 소수 클래스(불량/이상)를 얼마나 잘 잡는지 중심으로 확인 | 항상 "정상"이라 답해도 정확도가 높은, 쓸모없는 결과를 그대로 전달 |
| 8. 제조적 해석 | 결과를 공정 용어로 재설명, 설비/품질 이상 재구분 | 같은 신호가 다른 원인(예열 vs 불량)을 가리킬 수 있음 | 중요 변수가 원인 변수인지 결과성 변수인지 공정 흐름과 대조 | 관리해도 소용없는 변수를 관리 대상으로 잘못 추천 |
| 9. 현장 적용 + 한계 정리 | "누가, 무엇을, 언제 다르게 해야 하는가" + 놓친 부분 기록 | 실행 가능한 형태가 아니면 현장에 반영되지 않음 | 실행할 사람(작업자/설비관리자/공정엔지니어)을 명시 | 아무도 실행하지 않는 "보고서용 분석"이 됨 |

| 제조현장 문제 이해도 | 10 | 0.도메인 이해 |
| 제조AI데이터셋 이해도 | 10 | 0, 2, 4 |
| 문제 정의 체계성 | 10 | 1.문제정의 |
| 분석모델 독창성 | 10 | 5.파생변수, 6.모델링 |
| 분석 과정 타당성 | 10 | 2~7 전 과정의 논리적 일관성 |
| 결과해석 우수성 | 10 | 8.설비/품질 이상 구분, 제조적 해석 |
| 결과물 작성 충실성 | 10 | 보고서 전체 |

**발표평가 (정성 100)**

| 지표 | 배점 | 기여 단계 |
|---|---|---|
| 발표능력 우수성 | 10 | 발표 자체 |
| 문제 해결 독창성 | 20 | 1.문제정의, 5.파생변수 |
| 분석 과정 적절성 | 20 | 2~7 |
| 분석모델 적용 가능성 | 20 | 9.현장 적용 |
| **분석모델 확장성(사업성 포함)** | **30** | **11.확장성 정리 — 단, 6단계부터 누적 준비 필요** |

> 발표평가에서는 **확장성이 30점으로 단일 최고 배점**입니다. 시간이 부족하면 모델 성능을 더 짜내기보다, "이 결과가 왜 다른 공정·업종에도 통하는가"를 설득력 있게 정리하는 쪽이 점수에 유리합니다. 확장성은 마지막에 몰아서 생각하지 말고 파생변수 설계 단계부터 계속 메모해두세요.

# 4. 대회 전까지 추진 방향

### 목표

각자 **공정 / 품질 / 설비** 관점 중 하나를 골라, 그 관점에 해당하는 데이터셋을 하나 선택해서 **모의 데이터분석을 직접 해보고, 팀 내에서 발표 + 피드백**을 받습니다. 목적은 정답을 맞히는 게 아니라, `3_데이터분석_프로세스`를 실제로 한 번 완주해보고 각자 다른 유형의 데이터를 접해보는 것입니다.

---

### 1. 역대 대회 출제 데이터셋은 이번 훈련에서 제외

실전 대회에서 그대로 나올 가능성이 있으니, 훈련용 선택지에서 미리 뺍니다.

| 회차 | 연도 | 출제 데이터셋 |
|---|---|---|
| 1회 | 2021 | 사출성형기 |
| 2회 | 2022 | 용해탱크 |
| 3회 | 2023 | 열처리 품질보증 |
| 4회 | 2024 | 주조 공정최적화 |
| 5회 | 2025 | 열처리 공정최적화 / 소성가공 품질보증 / 사출성형 공급망최적화 (3개 중 팀 선택) |

→ 제외 대상(7개): **사출성형기, 용해탱크, 열처리 품질보증, 주조 공정최적화, 열처리 공정최적화, 소성가공 품질보증, 사출성형 공급망최적화**

6회(2026) 실제 출제 데이터셋은 신청 마감(9/17) 이후 별도 공개 예정이므로, 공개되는 대로 다시 공유하겠습니다.

---

### 2. 카테고리별 후보 데이터셋

제외 7개와, 공정/품질/설비 어디에도 딱 맞지 않는 공급망·자원·생산계획 최적화류 8개(발주량 예측, 인력배치 등 경영·물류형 데이터)를 뺀 **35개**를 세 카테고리로 나눴습니다. (분류 기준: `2_도메인_조사자료` 4장의 "공정/품질/설비 데이터 차이")

#### 공정 관점 (공정조건 자체를 다루는, 4개)

| 데이터셋 | 우선순위 | 이런 걸 배울 수 있음 |
|---|---|---|
| 공정운영 최적화 (표면처리) | A | 표면처리 라인의 첫 단계 데이터. 이후 전해탈지/도금욕/크로메이트와 구조가 비슷해서, 여기서 익히면 다른 표면처리 데이터도 빠르게 이해됨 |
| 생산공정 최적화 (사출성형·콘택트렌즈) | A | "불량 여부를 맞히기"가 아니라 "어떤 조건을 쓰면 좋을지 추천"하는 문제로 관점이 바뀌는 사례 |
| 용접 공정최적화 | B | 불량에 영향을 주는 변수 구간을 XGBoost/LightGBM으로 찾아 관리 구간을 제시하는 방식 |
| 의류 공정최적화 (염색) | C | 품질예측모델 + 유전알고리즘을 결합해 최적조건을 도출하는 2단계 구성 |

#### 품질 관점 (완제품의 양/불·품질수치를 다루는, 16개)

| 데이터셋 | 우선순위 | 이런 걸 배울 수 있음 |
|---|---|---|
| 주조 품질보증 (다이캐스팅) | A | 컬럼 헤더 자체가 `공정조건→센서→불량유형`으로 그룹화된, "공정→품질" 흐름을 가장 잘 보여주는 데이터 |
| 머신비전 (열화상) | A | 이미지 1장 = 양/불 라벨 1개인 순수 "이미지 분류"의 대표 사례 |
| X-ray 검사장비 | A | 이미지 안에서 이물질 "위치"까지 찾는 "객체탐지" 문제의 대표 사례 |
| CNC 머신 | A | 가공조건(조건표) + 원본 시계열을 조인해서 분석해야 하는, 파일이 여러 개인 실전형 구조 |
| 용접기(스팟용접) | A | 라벨이 아예 없어서 "비지도 이상치탐지"로 접근해야 하는 사례 |
| 전자부품(음향기기) 품질보증 | A | 50개 중 유일한 오디오 데이터 |
| 정밀가공 품질보증 | B | 원본 시계열이 아니라 이미 통계 요약(평균/최댓값 등)된 형태 — 실전에서 자주 만나는 파생변수 활용형 |
| 화장품 품질보증 | B | 공정 센서(수만 행)와 품질검사표(수십 행)의 측정 빈도가 크게 다른 경우를 다루는 연습 |
| 배터리팩 품질보증 | B | 셀 176개 전압을 개별 컬럼으로 갖는, "완제품=부품 집합" 구조 |
| 기계부품 품질보증 (냉간단조) | B | 결측치가 실제로 많은 데이터 — 결측 처리 연습에 적합 |
| 의류 품질보증 (염색) | B | 색상이라는 특이한 품질 기준(색차)을 다루는 사례 |
| 프레스기 | B | 라벨 없이 군집화(GMM)로 불량 유형 자체를 나눠보는 접근 |
| 살균기 | B | Decision Tree로 품질 판정에 중요한 변수를 해석 가능한 형태로 뽑는 연습 |
| 품질이상탐지 (전해탈지/도금욕/크로메이트) | B | 센서 로그 + 별도 불량Lot목록을 결합해야 라벨이 생기는 실전형 구조 |
| 소성가공 품질보증(압출) | B | 대회 5회 출제작(제외 대상)과 자매 데이터 — 참고만, 실제 훈련은 다른 걸로 |
| 제조현장용 OCR / Scene-Text | B | 이미지 기반 "측정 자동화" 특수 사례 (숫자 인식) |

#### 설비 관점 (설비 자체의 물리적 상태를 다루는, 15개)

| 데이터셋 | 우선순위 | 이런 걸 배울 수 있음 |
|---|---|---|
| 열처리 예지보전 | A | "로 내부가 860℃라 사람이 수시로 못 본다"는, 예지보전이 왜 필요한지 가장 명확하게 보여주는 사례 |
| 로봇용접 예지보전 | A | 진동+전류 두 신호를 결합한, 완성도 높은 예지보전 정석 사례 |
| Ford 엔진 진동 | A | 이미 정제된 공개 벤치마크. "파형=관측치 1개"라는 형태를 가장 쉽게 연습 가능 |
| 회전기계 고장유형 | A | 고장 데이터가 부족해 일부러 고장을 낸 실험장치(testbed)로 모은 데이터 — 불균형 문제의 원인을 체감 |

| CNC 머신 | A | (품질 관점과 동시에 설비 관점도 가능 — 공구마모 축으로 보면 설비 데이터) |

| 정밀가공 자원최적화(레이저홀) | B | 이름은 "자원최적화"지만 실제로는 레이저 반사광 이상탐지 — 이름만 보고 판단하면 안 되는 사례 |
| 소성가공 예지보전 | B | 유압펌프 진동/전류로 고장을 조기 탐지 |

| 사출성형 예지보전 | B | 완제품 품질이 아니라 설비 자체 상태를 보는 사출성형 데이터 (사출성형기는 품질 관점 데이터셋도 따로 있어 비교 가능) |

### 3. 진행 방식 제안

1. **선택**: 각자 공정/품질/설비 중 하나를 고르고, 그 안에서 데이터셋 1개를 선택 (되도록 서로 겹치지 않게 조율, A급부터 우선 고려)
2. **분석**: `3_데이터분석_프로세스`의 단계를 따라 모의 분석 진행 (KAMP AI-PaaS 또는 KAMP-NOTE 활용 가능)
3. **발표**: 각자 짧게 발표 — 어떤 도메인 문제였는지, 어떤 문제정의를 세웠는지, 어떤 결과가 나왔는지, 확장 가능성은 무엇인지
4. **피드백**: 팀원들이 서로 `3_데이터분석_프로세스` 4장의 평가지표 관점(특히 문제정의 체계성 / 결과해석 우수성 / 확장성)으로 피드백
5. 이 과정을 통해 팀 전체가 공정/품질/설비 세 관점을 모두 한 번씩 경험하고, 실제 대회 데이터셋이 무엇이든 빠르게 적응할 수 있도록 합니다.
