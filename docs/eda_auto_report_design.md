# EDA 자동화 & 리포트 생성 모듈 — 설계 검증 및 최종안 (v2)

> 목적: KAMP 경진대회 당일, 확정된 데이터셋의 표 파일(CSV/TXT — 이미지·파형 제외, §0-1)과 Guideline PDF를 넣으면 (1) 사람이 보는 시각화 중심 PDF, (2) AI Agent 컨텍스트용 구조화 파일(Markdown/JSON)을 자동 생성한다. 데이터 유형에 따라 실행되는 분석 항목이 달라지는 조건부 파이프라인이다.
>
> §0의 실측 검증 결과(실제 KAMP CSV를 열어 확인한 구조적 사실)는 v2에서도 그대로 유효하다. 다만 아래 v2 원칙과 충돌하는 **처방적 내용(권장 로직)** 은 v2 기준으로 교체됐다.

## v2 개정 (최종 설계 원칙 — 이 절이 이하 모든 내용보다 우선한다)

v1에는 EDA가 도메인 판단·변환 권장·알고리즘 추천을 하는 부분이 있었다. v2는 **"EDA는 데이터를 해석하는 모듈이 아니라 객관적으로 관찰하고 구조화하는 모듈"** 이라는 원칙으로 아래를 교체했다.

| # | v1 (폐기) | v2 (현행) | 이유 |
|---|---|---|---|
| 1 | IQR 공식을 모든 수치형에 일괄 적용 | **IQR=0이면 해당 변수 SKIP** + unique/mode/mode_ratio/min/max/사유 기록 | 제어된 공정 변수는 Q1=중앙값=Q3이 되어 정상 편차까지 전부 이상치로 오판정(실측: EX2/EX3/EX4.MELT_TEMP 14~33%). "IQR=0 → 이상치 없음"으로도 처리하지 않고, 대체 탐지 기법을 자동 투입하지도 않는다 |
| 2 | 왜도가 크면 "로그 변환 검토" 문구 생성 | **왜도는 통계량으로만 제시**, 변환 권장 문구 전면 삭제 | 제조 데이터의 큰 왜도는 clipping·saturation·제어값·운전 모드로 정상 발생 가능. 변환 판단은 후속 단계의 몫 |
| 3 | `n_unique<=10 → categorical`, `unique_ratio>=0.95 → id_like` 등 추론 | **Guideline 메타데이터 우선, 없으면 dtype 기준**. 고유값 수로 역할을 바꾸지 않음 | 제조 데이터에는 값 종류가 적은 discrete numeric(제어 설정값)이 정상적으로 존재. EDA는 분류가 아니라 검증을 한다 |
| 4 | target 소수 클래스 비율<10% → DBSCAN 우선 | **KMeans 단일화**(실루엣으로 k 선택), target 정보는 군집 알고리즘 선택에 전달하지 않음 | DBSCAN은 비지도 기법이며 target label 불균형과 논리적 연결이 없다 |
| 5 | 19번 Feature Engineering Hints 섹션(제거/결합/파생/변환 권장) | **섹션 삭제**, 18번을 "Key Observations(관찰 사실 종합)"으로 대체 | EDA는 FE·변환·모델을 권장하지 않는다 |
| 6 | 조건 미충족 분석은 리포트에서 조용히 누락 | **전 분석 상태 기록**: SUCCESS / SKIPPED / NOT_APPLICABLE / FAILED + 사유 | SKIP은 오류가 아니라 정상 동작이며, 추적 가능해야 한다 |
| 7 | Guideline PDF는 파싱하지 않고 사람이 target만 지정 | **PDF → Metadata → 검증 → EDA** 계층 추가(`eda_report/metadata/`) | Guideline의 변수 설명·타입·시간축을 EDA 실행 전에 활용. 단, PDF에서 컬럼명을 생성하지 않고(실제 데이터에 있는 이름만 매칭) 타입도 검증 후에만 사용 |
| 8 | rolling window 60 고정, threshold 12개 모듈에 산재 | `AnalysisThresholds`로 통합 + 데이터 길이 기반 산출, 사용값을 Manifest에 기록 | 근거 없는 고정 상수 제거 |

**금지 표현**: "~의 원인이다", "~를 유발한다", "~는 공정 이상을 의미한다", "~ 변환을 권장한다", "중요 변수이다".
**사용 표현**: "~가 관찰됨", "~의 값은 X로 나타남", "분석 조건을 충족하지 않아 수행하지 않음", "IQR=0으로 해당 기준으로는 판정할 수 없음".

통계적 이상치 ≠ 공정 이상, 상관관계 ≠ 인과관계를 리포트 문구와 용어집에 명시한다.

### 이 문서 작성 전 확인이 필요한 전제 하나

`docs/eda_gui_spec.md`는 기존 Streamlit 도구의 설계 원칙으로 **"의미 자동 추론 금지"**와 함께 **모델 기반 이상탐지(Isolation Forest 등), 자동 리포트 생성(PDF/HTML), 종합 Auto EDA를 명시적으로 비목표(non-goal)** 로 규정했다. 이번 신규 모듈은 그 결정을 뒤집는 것이므로(사용자가 "처음부터 다시" 요청), 의도된 피벗으로 이해하고 진행한다. 다만 **"의미는 확정하지 않고 구조적 후보만 제시한다"는 원칙**(예: target 컬럼은 자동 추론하지 않고 가이드라인 문서/사용자 설정으로만 확정)은 이번 설계에도 그대로 가져왔다 — 아래 각 항목에서 이 원칙이 어떻게 적용되는지 명시했다.

## 0-1. 입력 파일 형식 범위 (CSV / TXT만, 이미지·파형 제외)

사용자 확정: **파형(오디오 wav)·이미지 데이터는 이 모듈의 범위에서 완전히 배제**, **CSV 외에 TXT도 읽을 수 있어야 함**.

### TXT가 실제로 어떤 형태인지 확인

`02_FordEngine` 표본을 열어보니 TXT 파일 안에서도 성격이 갈렸다.

| 파일 | 실제 내용 | 처리 방침 |
|---|---|---|
| `FordA_TRAIN.txt` | 공백(가변 개수) 구분 숫자 행렬, **헤더 없음**, 1열이 클래스 레이블(-1/1), 나머지 500열이 시계열 측정값 | **지원 대상** — 구분자를 콤마 외에 탭/가변 공백까지 자동 감지해야 하고, 헤더 없는 CSV와 동일한 처리 경로(§1의 헤더 없음 로직) 재사용 |
| `FordA.txt` | 대회 설명이 적힌 순수 영문 산문(표가 아님) | **비대상** — 확장자가 txt여도 표 형태가 아니면 파싱 대상에서 제외. 애초에 사람/에이전트가 "이 파일이 데이터 파일이다"라고 지정해서 넘기므로, 이런 설명 파일이 잘못 지정될 가능성은 낮지만 방어적으로 "표로 파싱 가능한지" 최소 검증(행별 컬럼 수 일관성 등)은 필요 |
| `01_OCR`의 `train_data.txt` | 이미지 파일 경로 목록(`0/00001_3.jpg` 한 줄에 하나) | **비대상** — 표가 아니라 파일 경로 리스트. 애초에 `01_OCR`은 이미지 데이터셋이라 이번 배제 대상 |

**ARFF(`FordA_TRAIN.arff` 등)는 이번 범위에서 제외한다** — WEKA용 구조화 헤더(`@relation`/`@attribute`/`@data`)를 가진 별도 포맷이라 CSV/TXT 파서로 다루기 어렵고, 같은 데이터의 `.txt` 버전이 이미 존재해 정보 손실이 없다. 별도 요청 시에만 추가 검토.

### 입력 스코프의 실제 경계

모듈은 **폴더를 스캔해 "진짜 데이터 파일"을 알아서 찾지 않는다** — 사람(또는 에이전트)이 지정한 CSV/TXT 파일 1개를 입력으로 받는다(§1 원칙과 동일: 의미 판단은 항상 사람의 몫). 따라서 `06_Machinevision`처럼 폴더 안에 이미지 zip과 진짜 데이터 CSV(`left_data.csv`)가 섞여 있어도, 사람이 CSV 경로를 정확히 지정하기만 하면 문제가 없다.

### 실측으로 확인된 위험: 50개 중 5개는 이 모듈로 아예 분석할 표 데이터가 없음

50개 폴더 전체를 스캔해 "실제 제조 측정값을 담은 표 파일"이 있는지 확인했다(단순 확장자 카운트가 아니라 내용까지 열어 확인).

| 데이터셋 | 실제 보유 파일 | 결론 |
|---|---|---|
| `01_OCR` (No.1) | jpg 이미지 + 이미지 경로 목록 txt | **표 데이터 없음** |
| `12_XrayInspection` (No.12) | bmp/jpg 이미지 + YOLO 라벨 txt(바운딩박스) | **표 데이터 없음** |
| `38_전자부품(음향기기)_품질보증` (No.47) | wav 오디오 348개뿐 | **표 데이터 없음** |
| `47_Scene-Text Recognition` (No.16) | jpg 이미지 + 코드/빌드 산출물 txt | **표 데이터 없음** |
| `48_제조현장 안전관리` (No.29) | CCTV 이미지 + YOLO 학습 로그 csv(손실값 추이, 제조 데이터 아님) | **표 데이터 없음** |

**이 5개(전체의 10%)가 대회 당일 무작위로 뽑히면, 이 EDA 모듈은 실행할 표 데이터 자체가 없다.** 이미지·파형을 명시적으로 배제하기로 한 이상 이 5개는 이 모듈의 범위 밖이라는 점을 감안하고 진행하되, 모듈이 이런 입력(비표형 파일, 또는 유효 컬럼이 0개)을 받았을 때 조용히 이상한 결과를 내지 않고 **"이 파일은 정형 표 데이터가 아니라 분석할 수 없습니다"라고 즉시 명확히 실패**하도록 방어 로직을 넣는 것을 권장한다.

## 2. 항목별 상세 검증

### 01. Dataset Overview
- **필요성**: 높음
- **확인되는 데이터 유형**: 전체 — 예외 없이 항상 필요
- **이 분석을 하는 이유**: 이후 모든 페이지의 "조건부 실행 여부"를 결정하는 입력값(행/열 수, dtype 분포)을 확정한다. 사람은 "이 데이터가 다룰 만한 규모인가"를 1초 안에 판단한다.
- **추천 시각화**: 숫자 카드(행/열/타입 구성/파일 크기) + dtype 구성 도넛 또는 막대 1개
- **페이지당 권장 그래프 수**: 1개(장식용), 나머지는 숫자 카드
- **자동 생성 조건**: 항상
- **생략 조건**: 없음
- **추가 설명 필요 여부**: 짧게(1~2문장)로 충분
- **주의사항**: "파일 크기 = 데이터 품질"이 아님을 암묵적으로 오해하지 않게 문구 주의
- **FE 연관성**: 낮음(구조 파악 단계)

### 02. Column Profile
- **필요성**: 높음
- **확인되는 데이터 유형**: 전체
- **이 분석을 하는 이유**: 뒤의 모든 분석에서 "이 변수를 계산에 넣을지 뺄지"를 결정하는 필터 역할. 실측에서 상수 컬럼(`04`의 Mold_Temperature 다수), ID형 고카디널리티 컬럼(`20`의 item 6,617종), 100% 결측 컬럼(`42`)이 실제로 나왔다 — 이걸 걸러내지 않으면 뒤의 상관/PCA/분포 분석이 전부 오염된다.
- **추천 시각화**: 테이블(변수명·dtype·결측률·unique·unique비율·constant 여부·ID-like 여부·샘플값) — 시각화보다 **정확한 표**가 핵심
- **페이지당 권장 그래프 수**: 0(표 중심), 변수 30개 초과 시 페이지 분할
- **자동 생성 조건**: 항상
- **생략 조건**: 없음
- **추가 설명 필요 여부**: "constant/ID-like로 표시된 변수는 이후 분석(상관·분포·PCA)에서 자동 제외됩니다"라는 안내 필수
- **주의사항**: **"ID-like/constant"는 구조적 판정(고유값 비율, nunique)이며 "이 컬럼이 식별자다"라는 의미 판단이 아니다** — 실제로 저카디널리티 정수 컬럼(`03_CNC`의 값 3~15종)이 진짜 설비코드인지 그냥 반올림된 연속값인지는 가이드 문서 없이는 알 수 없음. 문구에 "~로 추정됨" 수준으로만 표현.
- **FE 연관성**: 상수/100%결측 컬럼 = 즉시 제거 후보, ID-like = 모델 입력에서 제외하되 groupby 키로는 활용 후보

### 03. Missing Values
- **필요성**: 높음
- **확인되는 데이터 유형**: 전체(정도 차이만 있을 뿐 결측 없는 제조 데이터는 거의 없었음 — 13개 표본 중 결측 0인 건 2~3개뿐)
- **이 분석을 하는 이유**: 단순 "몇 % 비었다"가 아니라 **결측이 무작위인지 구조적인지**를 구분해야 처리 방법이 달라진다. 실측 사례: `04`의 `Reason`은 불량일 때만 채워지는 조건부 결측(정보성 결측), `49`는 여러 컬럼이 정확히 같은 비율(7.9%)로 함께 비어 초기 가동 구간 공통 결측으로 추정, `42`는 컬럼 전체가 통째로 비어(다른 설비 로그가 이어붙여진 흔적).
- **추천 시각화**: 컬럼별 결측률 막대(내림차순) + missingness 매트릭스(행=샘플링된 관측치, 열=변수, 있음/없음 흑백) 1개
- **페이지당 권장 그래프 수**: 2개
- **자동 생성 조건**: 결측 존재 시(결측 0%면 "결측 없음" 한 줄로 대체하고 페이지 스킵)
- **생략 조건**: 전체 결측률 0%
- **추가 설명 필요 여부**: 함께 비는 컬럼 쌍이 발견되면 "OO와 OO는 항상 함께 결측됨 — 같은 원인(예: 특정 설비 미가동)일 가능성"처럼 짧은 자동 문장 필요
- **주의사항**: 결측 원인을 "왜"까지는 데이터만으로 확정할 수 없음 — 추정 문구 톤 유지(옛 GUI 설계 원칙과 동일)
- **FE 연관성**: 조건부 결측 발견 시 "결측 여부 자체를 이진 파생변수로" 만드는 것이 실제로 유용한 경우가 많음(`04`의 `Reason` 존재 여부 = PassOrFail과 사실상 동치)

### 04. Descriptive Statistics
- **필요성**: 높음 / **확인 유형**: 수치형 변수가 1개 이상인 전체
- **이유(의사결정)**: 변수의 스케일 차이(예: `04`의 `Barrel_Temperature`~200대 vs `Injection_Time`~한 자릿수)를 미리 파악해야 뒤의 PCA/상관 분석에서 스케일링 필요 여부를 판단할 수 있다.
- **추천 시각화**: 없음(표), skew 절대값 상위 컬럼은 볼드/색상 강조
- **페이지당 권장**: 표(변수 20개 넘으면 페이지 분할)
- **생성 조건**: 항상(수치형 존재 시)
- **생략 조건**: 수치형 0개
- **설명 필요 여부**: 최소한("평균과 중앙값 차이가 크면 치우침" 정도 각주)
- **주의사항**: `describe()`를 상수/ID-like 컬럼까지 포함해서 계산하면 무의미한 행이 섞임 — 02번에서 제외 표시된 컬럼은 여기서도 제외
- **FE 연관성**: 왜도 큰 변수 → log/box-cox 변환 후보

### 05. Numerical Distribution
- **필요성**: 높음 / **확인 유형**: 수치형 다수 존재 시
- **이유**: 변수가 정규에 가까운지, 이봉/다봉인지(다봉이면 숨은 하위 그룹 존재 신호 — Clustering 항목과 연결), 특정 값에 쏠려 있는지(예: 설정값 근처에서만 값이 찍히는 제어 변수) 확인
- **추천 시각화**: Histogram+KDE, Boxplot
- **페이지당 권장**: 4개(2x2) — 변수 많으면 대표 변수 선정 후 페이지 추가
- **생성 조건**: 항상(수치형 존재 시)
- **생략 조건**: 없음(단, 대표 변수 선정 로직 적용)
- **설명 필요 여부**: 왜 이 변수들이 "대표"로 뽑혔는지(분산 상위/왜도 상위/사용자 지정) 한 줄
- **주의사항**: 상수 컬럼을 히스토그램으로 그리면 막대 하나만 보임 — 02번에서 제외된 컬럼은 자동 스킵
- **FE 연관성**: 다봉 분포 발견 → 잠재 카테고리(운전모드 등) 파생 후보, 특정 값 쏠림 → 이산화(binning) 후보

### 06. Categorical Distribution — *조건부*
- **필요성**: 중간(범주형 컬럼이 있는 데이터에서는 높음) / **확인 유형**: `20`(생산계획), `19`(연관분석용), `04`의 `PART_NO/PART_NAME` 등
- **이유**: 특정 범주(제품/설비/공정 코드)에 데이터가 쏠려 있는지 확인 — 쏠림이 심하면 그 범주에 대해서는 통계적으로 결론 내리기 어렵다는 신호
- **추천 시각화**: 막대그래프(Top-N + "기타" 묶음)
- **페이지당 권장**: 4개(작은 변수 다수면 grid)
- **생성 조건**: usable categorical(구조적으로 nunique 2~50, ID-like 제외) 1개 이상
- **생략 조건**: 범주형 없음, 또는 전부 ID-like(예: `20`의 `item`)
- **설명 필요 여부**: Top-N 기준(예: "상위 10개 외 33개 범주는 '기타'로 묶음") 명시 필수
- **FE 연관성**: 희귀 범주 통합(rare category grouping) 후보 도출

### 07. Outlier Analysis (IQR + Isolation Forest)
- **필요성**: 높음(IQR) / 조건부(Isolation Forest)
- (딥다이브는 §3에서 상세)
- **추천 시각화**: Boxplot(대표 변수 grid) + (조건 충족 시) 다변량 이상치 산점도(PCA 2D 위에 IF 판정 결과 색칠)
- **페이지당 권장**: 4개(IQR 단변량) / 1개(IF 다변량, PCA와 결합)
- **생성 조건**: IQR은 수치형 1개 이상이면 항상, IF는 유효 수치형≥3 & 행≥500
- **생략 조건**: IF 조건 미충족 시 IF만 생략(IQR은 유지)
- **주의사항**: "통계적 이상치이며 실제 설비 고장/불량을 의미하지 않는다"는 고지 문구 필수(기존 설계 원칙 계승)
- **FE 연관성**: 이상치 비율 높은 변수 → 클리핑/윈저라이징 후보, IF가 잡은 다변량 이상치 → 별도 anomaly flag 파생변수 후보

### 08. Correlation Analysis
- **필요성**: 높음 / **확인 유형**: 유효 수치형 2개 이상
- **이유**: 중복 정보를 가진 변수쌍(다중공선성) 식별 + 변수군 파악. 실측: `04`의 `Barrel_Temperature_1~7`, `50`의 `top_temp1~4`/`bottom_temp1~4`처럼 이름부터 그룹인 변수들의 실제 상관 강도를 확인하는 용도로 실질적 가치가 컸다.
- **추천 시각화**: Pearson heatmap 1개(계층적 군집 순서로 재배열), 필요 시 Spearman은 AI Context에만(§3 Network 딥다이브 참고)
- **페이지당 권장**: 1개(크게)
- **생성 조건**: 유효 수치형 ≥ 2
- **생략 조건**: 유효 수치형 < 2
- **설명 필요 여부**: "0.9 이상 상관은 사실상 같은 정보"처럼 해석 기준선 제시
- **주의사항**: 상수/제로분산 컬럼 포함 시 상관계수가 NaN 또는 무의미 — 02번 필터 필수 선행
- **FE 연관성**: 다중공선성 변수 제거/그룹 대표값 추출의 직접 근거

### 09. Feature Relationship (Scatter)
- (딥다이브 §3)
- **필요성**: 중간 / **확인 유형**: 상관분석 실행된 모든 경우
- **추천 시각화**: 선형 Top-N + 비선형 후보 Top-N 산점도(LOWESS 추세선 포함)
- **페이지당 권장**: 4개
- **생성 조건**: 유효 수치형 ≥ 2
- **생략 조건**: 없음(08 실행 시 항상 같이)
- **FE 연관성**: 비선형 관계 발견 시 교호작용/다항 피처 후보

### 10. Categorical × Numerical — *조건부*
- **필요성**: 중간~높음(그룹 변수가 실제로 있을 때는 매우 높음) / **유형**: `04`의 `PART_NAME`, `19`의 `EQUIP_ID`
- **이유**: 옛 GUI 검증에서도 "그룹별 비교"가 MVP 필수로 확정됐을 만큼 실질 가치가 확인된 항목. 설비/제품별로 공정변수 분포가 다른지 확인
- **추천 시각화**: Boxplot 또는 Violin(그룹 5개 이하일 때), 그룹 많으면 Top-N 그룹만
- **페이지당 권장**: 2개
- **생성 조건**: usable categorical ≥ 1 AND 유효 수치형 ≥ 1
- **생략 조건**: usable categorical 0개
- **주의사항**: 그룹별 표본 수 차이가 크면(한 그룹 5건, 다른 그룹 5만 건) 박스플롯이 왜곡되어 보일 수 있음 — 그룹별 n수를 항상 같이 표기
- **FE 연관성**: 그룹별 평균 차이가 큰 변수 = 그룹을 원-핫 인코딩할 가치가 높다는 신호

### 11. Categorical × Categorical — *조건부*
- **필요성**: 낮음~중간(표본 13개 중 실제로 usable categorical이 2개 이상인 건 `20`, `04` 정도로 소수) / **유형**: 범주형이 여러 개인 관계형 데이터
- **추천 시각화**: Crosstab heatmap + Cramér's V 값
- **페이지당 권장**: 1개
- **생성 조건**: usable categorical ≥ 2
- **생략 조건**: usable categorical < 2 (제조 센서 중심 데이터에서는 이 조건으로 상당수 스킵될 것으로 예상)
- **FE 연관성**: 특정 조합에서만 나타나는 패턴 = 조합형 파생변수 후보

### 12. PCA — *조건부* (딥다이브 §3)
- **필요성**: 조건부로 높음 / **생성 조건**: 유효 수치형 ≥ 5 AND 유효 수치형 중 제로분산 아닌 것이 최소 5개
- **생략 조건**: 유효 수치형 < 5
- **페이지당 권장**: 2개(① Scree/설명분산 + 2D scatter, ② Loading 표 또는 bar)

### 13. Clustering — *조건부* (딥다이브 §3)
- **생성 조건**: 유효 수치형 ≥ 2 AND 행 ≥ 100
- **페이지당 권장**: 1~2개(① 2D 산점도+elbow/silhouette 작게, ② Cluster Profile 표/막대 — **이 페이지가 더 중요**)

### 14. Correlation Network — *PDF 제외, AI Context만*
- (딥다이브 §3)

### 15. Target Analysis — *조건부, 최고 우선순위*
- **생성 조건**: 가이드라인 문서 또는 사용자가 target 컬럼(1개 또는 다중 이진 컬럼 세트)을 명시적으로 지정한 경우에만. **자동 추론하지 않는다** — `04`의 `PassOrFail`처럼 이름이 직관적인 경우도 있지만 `37`처럼 후보가 26개인 경우도 실측으로 확인됐기 때문에, "그럴듯한 이름"으로 자동 판정하면 오판 위험이 큼.
- (타입별 세부는 §3)

### 16. Time Series Analysis — *조건부*
- **필요성**: 높음(해당 시) / **생성 조건**: datetime으로 파싱 가능한 컬럼이 있거나(파싱 성공률 ≥ 95%), 명시적 시간 컬럼은 없지만 데이터가 순서 있는 로그로 확인된 경우(예: `13`처럼 파일명 자체가 순서를 내포)
- **추천 시각화**: 추세선 + rolling mean/std, 결측 구간은 끊어서 표시
- **페이지당 권장**: 2개
- **생략 조건**: datetime 파싱 실패 & 순서 정보 없음
- **주의사항**: `50`처럼 "date" 컬럼명이 실제로는 시각(time-of-day)만 담고 있는 사례가 실측에서 확인됨 — 컬럼명을 믿지 말고 실제 파싱 결과(연/월/일 포함 여부)로 판단해야 함. ACF/PACF는 계절성보다 "공정 드리프트"가 중요한 제조 데이터 특성상 우선순위를 낮춤(§3에서 상술)
- **FE 연관성**: rolling/lag/diff 파생변수 후보, 드리프트 구간 식별 시 구간별 파생변수

### 17. Association Analysis — *조건부, 실제 발동 빈도 낮을 것으로 예상*
- (딥다이브는 다루지 않지만 조건 재정의) **생성 조건**: usable categorical(사전 Top-N 버킷팅 후 카디널리티 ≤ 30)이 2개 이상 존재. 실측 표본 13개 중 이 조건을 만족할 후보는 `19`(버킷팅 필요), `20` 정도뿐 — 센서/공정 중심 데이터에는 대부분 해당 없음을 사전에 확인.
- **생략 조건**: 조건 미충족(대부분의 경우). 카디널리티가 너무 높으면(`19`의 545종처럼) Top-N 버킷팅으로도 부족할 수 있어, 버킷팅 후에도 조합 수가 과도하면 생략하고 "최빈 조합 Top 20"만 AI Context에 텍스트로 남김

## 3. 딥다이브

### PCA
- **왜 수행하는가**: 제조 데이터의 수십 개 센서는 실제로는 소수의 물리적 구동 요인(온도군, 압력군, 속도군)에서 파생된 상관된 신호인 경우가 많다(실측: `04`의 Barrel_Temperature 7종, `50`의 top/bottom_temp 각 4종). PCA는 "이 공정을 지배하는 실질적 자유도가 몇 개인지"와 "어떤 변수 묶음이 같은 신호를 반복 기록하는지"를 수치로 드러낸다.
- **2D 시각화로 실제로 보는 것**: 관측치(shot/lot/row)가 시간·설비·제품별로 군집을 이루는지, 정상/불량이 주성분 공간에서 시각적으로 분리되는지(분리되면 이후 분류 모델링이 잘 될 신호), 극단 이상치가 원점에서 멀리 떨어져 나타나는지.
- **Explained Variance를 반드시 보여줘야 하는 이유**: 2D 산점도는 "PC1+PC2가 전체 분산의 몇 %를 설명하는지"를 모르면 과신하기 쉽다. 예: 두 축이 30%만 설명한다면 그림에서 가까워 보이는 두 점이 실제 고차원에서는 멀 수 있다 — 이 수치 없이 2D 그림만 보여주는 것은 오해를 유발한다.
- **Loading의 FE 활용**: 절대값이 큰 변수 조합을 보고 "이 주성분은 사실상 Barrel_Temperature 그룹을 대표한다"처럼 해석 → 그 그룹을 평균/대표값 하나로 축약(차원 축소형 파생변수)하거나, 반대로 로딩이 전 주성분에서 낮은 변수는 주 변동에 기여가 적어 제거 후보로 검토.
- **변수 수가 적을 때도 가치가 있는가**: 5개 미만이면 압축 효과가 미미해 상관 heatmap/산점도로 충분히 대체된다. **PDF 전용 페이지로는 가치가 낮아 생략을 권장**(§1의 조건: 유효 수치형 ≥5).
- **스케일링 필요성**: 반드시 필요(표준화). 실측 근거: `04`에서 `Barrel_Temperature`(≈200대)와 `Injection_Time`(한 자릿수 초 단위)처럼 스케일이 수십~수백 배 차이나는 변수가 공존 — 스케일링 없이 PCA를 하면 사실상 "가장 큰 숫자의 분산"만 반영된다.
- **이상치의 영향**: PCA는 분산 최대화 방향을 찾으므로 극단 이상치 하나가 주성분 방향 자체를 왜곡한다. 실측에서 확인된 초기 가동 구간 공통 결측/이상(`49`)처럼 시작 구간에 비정상 값이 몰려 있는 경우, 결측 처리 이후에도 초반 값이 이상치로 남아 PCA를 왜곡할 수 있다. → PCA 전에 IQR 이상치를 표시만 하고(자동 제거는 하지 않음, 의미 판단 회피 원칙과 일관) "이상치 포함/제외" 두 버전을 병기하거나 최소한 각주로 영향 가능성을 명시.
- **수행하면 안 되는 조건**: (a) 유효 수치형 5개 미만 (b) 대부분의 수치형이 상수/거의 상수라서(`04`처럼) 실질 유효 차원이 1~2개뿐인 경우 — 이때는 02번 Column Profile에서 상수 컬럼을 먼저 제외한 뒤 남는 유효 변수 수로 재판정.

### Clustering
- **제조 데이터에서의 의미**: 레이블 없이도 서로 다른 운전 조건/제품/공정 레짐이 섞여 있는지 발견하는 용도. `07_Press`처럼 군집화 결과 자체가 최종 산출물(정상+비정상 3종=4군집)인 경우도 실제로 존재한다.
- **K-means를 기본으로 해도 되는가**: 구현이 단순하고 해석이 쉬워 기본값으로는 적절하다. 다만 두 가지 조건에서는 부적절: (a) 클래스가 심하게 불균형한 이상탐지형 데이터(실측: `04`가 99.1%:0.9%) — K-means는 다수 클래스 내부를 억지로 여러 조각으로 쪼개고 소수 이상치는 무시하기 쉽다. (b) 군집이 구형이 아니라 "큰 정상 덩어리 + 소수 이상치" 형태(밀도 기반 구조)일 때.
- **[v2 교체]** 위 (a)(b) 논의는 *데이터 특성에 따라 적합한 기법이 다를 수 있다*는 일반론으로만 유효하며, **알고리즘 자동 전환 로직은 폐기했다**. target 불균형은 비지도 기법 선택의 근거가 아니다(v2 개정 #4). 현행 구현은 KMeans 하나로 고정하고 k는 실루엣 점수로 선택하며, 사용한 알고리즘·k·탐색 점수·전처리를 전부 기록한다. 기법을 바꿀 필요가 있다면 EDA가 자동 판단하지 않고 사용자가 결정한다.
- **PDF에서 이해하기 쉬운 표현**: 2D(PCA 또는 대표 변수 2개) 산점도 + 군집 색상은 보조 그림 크기로, elbow/silhouette는 더 작게. **Cluster Profile(군집별 평균값 비교 표/막대, 예: "Cluster 2는 Vibration↑ Pressure↑")을 반드시 함께 배치**.
- **군집 탐색 vs Cluster Profile 중 중요도**: **Cluster Profile이 더 중요하다.** 군집 번호 자체는 무의미하고, "이 군집이 다른 군집과 어떻게 다른가"라는 해석이 실제 의사결정과 FE로 이어진다.
- **FE 기여**: 군집 라벨을 새 범주형 파생변수로 추가, 또는 군집을 가장 잘 가르는 변수를 우선순위 높은 피처 후보로 승격.

### Correlation Network
- **Heatmap과의 차이**: heatmap은 pairwise 강도를 정확한 값으로 비교하는 데 강하고, network는 "몇 개의 변수 덩어리가 있는지" 위상 구조를 직관적으로 보여주는 데 강하다. 그러나 상관 기준으로 재정렬(hierarchical reorder)한 heatmap도 사실상 같은 "블록 구조"를 보여줄 수 있어 정보 중복이 크다.
- **유용해지는 변수 규모**: 대략 30개 이상, 특히 50개 이상(표본의 `37`, `42`)에서 매트릭스 판독이 어려워지며 네트워크의 상대적 이점이 생긴다.
- **threshold 설정**: 보통 `|r|≥0.7` 또는 상위 N% 엣지. 다만 임계값 선택 자체가 자의적이라 heatmap 대비 추가 정보이득이 크지 않다.
- **실제 정보 증가 여부**: 크지 않다고 판단. 표본에서 `37`/`42`도 변수명 규칙(`Barrel_Temperature_1~7`, `top_temp1~4` 등)만으로 이미 그룹을 짐작할 수 있고, 재정렬된 heatmap으로 충분히 확인 가능했다.
- **결론**: **PDF에는 넣지 않는다.** 대신 그 원재료인 "임계값 이상 상관쌍 목록(노드-엣지 리스트)"을 **AI Context(JSON)에만** 저장한다 — 에이전트가 "이 변수들은 사실상 같은 그룹"이라 판단할 때 이미지보다 이 리스트가 훨씬 다루기 쉽다.

### Scatter Plot (Feature Relationship)
- **"상관 높은 Top-N pair" 방식의 적절성**: 1차 근사로는 합리적이다(구현이 쉽고 강한 관계 대부분을 캡처). 그러나 U자형/비단조 관계, 문턱값 이후 포화되는 공정 특성적 관계, 이분산성은 놓칠 수 있다.
- **보완책 제안**:
  1. Pearson 외에 Spearman(단조적 비선형 포착)과 mutual information(비단조 포함 포착)을 함께 계산해, "Pearson은 낮은데 MI가 높은" 쌍을 별도로 "비선형 관계 후보"로 선정 — 예: 선형 Top-N + 비선형 후보 Top-(N/2)로 나눠 배치.
  2. 각 산점도에 LOWESS 추세선을 얹어 비선형 패턴이 있으면 시각적으로 바로 드러나게 한다.

### Outlier Analysis (IQR + Isolation Forest)
- **IQR을 쓰는 시점**: 변수 단위(univariate) 극단값을 빠르고 해석 가능하게 보고 싶을 때 — 항상 기본 실행(계산 비용 거의 없고 "왜 극단적인지" 바로 이해 가능).
- **Isolation Forest가 유용한 시점**: 개별 변수는 정상 범위지만 "변수 조합"이 비정상인 다변량 이상치를 잡고 싶을 때(예: 온도도 정상, 압력도 정상이지만 그 조합이 이례적인 경우). **조건**: 유효 수치형 ≥3 AND 행 ≥500 — 이 미만에서는 밀도 추정이 불안정해 신뢰하기 어렵다.
- **두 결과가 다를 때의 해석**: IQR만 잡고 IF는 못 잡음 → 단변량 극단이지만 다른 변수와의 관계는 정상적(측정 이슈 가능성). IF만 잡고 IQR은 못 잡음 → 개별 변수는 정상 범위지만 조합이 이례적 — 공정 이상 신호일 가능성이 더 크다. **Key Findings에서 이 교집합/차집합을 텍스트로 명시해야 한다.**
- **모든 데이터셋에 IF를 돌리는 게 적절한가**: 아니다. 위 조건 미충족 시 생략, 초고차원(수십~수백 변수)에서도 대표 변수 subset(예: 분산 상위 15개)에만 적용하는 것을 권장 — 전체 변수에 그대로 적용하면 해석이 오히려 어려워진다.

## 4. 데이터 유형별 자동 분석 선택 규칙

사전 처리(02번 Column Profile)로 아래 변수를 계산한 뒤 적용한다.
- `numeric_effective`: 수치형이면서 상수/100%결측/ID-like가 아닌 컬럼 수
- `categorical_usable`: object/저카디널리티 수치형 중 `2 ≤ nunique ≤ 50`이고 ID-like가 아닌 컬럼 수
- `datetime_ok`: 파싱 성공률 ≥95%인 datetime 후보 컬럼 존재 여부(컬럼명이 아니라 **파싱 결과**로 판단 — `50`의 `date` 컬럼명 오해 사례 참고)
- `target_provided`: 가이드 문서/사용자 설정으로 target(단일 또는 다중 이진 세트)이 주어졌는지
- `n_rows`: 행 수

```
[항상 실행]
00 표지/매니페스트, 01 Overview, 02 Column Profile, 04 Descriptive Statistics,
05 Numerical Distribution(numeric_effective>=1), 07-IQR(numeric_effective>=1),
18 Key Observations(관찰 사실 종합)

IF numeric_effective == 0
  → 04/05/07-IQR/08/09/12/13 전부 스킵, 02/06/10/11/17/18/19만으로 구성(순수 범주형 데이터 — 표본에는 없었으나 방어적으로 필요)

IF categorical_usable >= 1
  → 06 Categorical Distribution 실행

IF numeric_effective >= 2
  → 08 Correlation Analysis, 09 Feature Relationship 실행

IF categorical_usable >= 1 AND numeric_effective >= 1
  → 10 Categorical x Numerical 실행

IF categorical_usable >= 2
  → 11 Categorical x Categorical 실행

IF numeric_effective >= 5
  → 12 PCA 실행 (미만이면 스킵, AI Context에는 최소 계산치만)

IF numeric_effective >= 2 AND n_rows >= 100
  → 13 Clustering 실행
     IF target_provided AND minority_class_ratio < 0.10
        → [v2 폐기] target 정보는 군집 알고리즘 선택에 사용하지 않는다
     → 알고리즘: KMeans 고정, k는 실루엣 점수로 선택(탐색 점수 전부 기록)

IF numeric_effective >= 3 AND n_rows >= 500
  → 07-IsolationForest 추가 실행 (대표 변수 subset)

IF datetime_ok == True
  → 16 Time Series Analysis 실행
  ELSE IF 순서 정보만 존재(파일명/행 순서가 시간을 내포한다고 확인됨, `13` 사례)
  → 16을 "관측 순서 기준"으로 축소 실행(추세선만, rolling 중심)

IF target_provided
  → 15 Target Analysis 실행 (타입은 §3 표에 따라 분기)

IF categorical_usable >= 2 AND 각 컬럼의 (Top-N 버킷팅 후) 카디널리티 <= 30
  → 17 Association Analysis 실행
  ELSE
  → 17 스킵, "카디널리티 과다로 생략" 로그만 00번 매니페스트에 기록

14 Correlation Network → PDF에서는 항상 스킵(AI Context 전용, §3 결론)
```

## 5. PDF 페이지 구성 검증

**"1페이지 = 하나의 분석 질문" 원칙은 유지하되, 절대 규칙이 아니라 기본값으로 둔다.** 실측 근거: `02 Column Profile`과 `04 Descriptive Statistics`는 변수가 30개를 넘으면(`37`: 57, `42`: 58, `03`: 48) 표 하나가 A4 한 장에 안 들어간다 — 이 경우 "1항목=1페이지"를 억지로 지키기보다 "1항목=N페이지(표 자동 분할)"로 완화하는 것이 낫다.

**A4 기준 권장 사항**
| 구성 요소 | 권장 |
|---|---|
| 여백 | 상하좌우 15~20mm, 실사용 영역 약 170×240mm |
| 제목+한 줄 목적 | 페이지 상단 10~12% |
| "왜 필요한가" 짧은 설명 | 필요한 항목만, 5~8% (모든 페이지에 강제하지 않음 — 08 Correlation처럼 자명한 항목은 생략 가능) |
| 시각화 영역 | 60~70% |
| 주요 발견(자동 생성 문장) | 15~20%, 하단 고정 위치로 통일(사람이 매 페이지 같은 자리를 보면 되게) |
| 표가 메인인 페이지(02, 04) | 시각화 없이 표가 80%, 상단에 "제외된 컬럼 수" 요약 카드 |

**그래프 개수 균형**
- 단순 그래프(히스토그램/박스플롯): 페이지당 4개(2×2)까지 — 그 이상은 개별 그래프가 우표 크기가 되어 가독성이 급격히 떨어짐(실측: `42`처럼 numeric_effective가 30개를 넘는 경우 대표 12~16개만 개별 페이지에 4개씩 배치하고, 나머지는 "미니 스파크라인 그리드"(축 없이 모양만, 한 페이지에 20~30개) 1페이지로 압축)
- 복잡한 그래프(heatmap/PCA/네트워크류): 페이지당 최대 2개, 기본 1개 — 특히 heatmap은 변수 50개를 넘기면(`37`, `42`) 라벨이 겹치므로 폰트 축소보다 **변수명 계층적 재정렬 + 상위 상관쌍 표를 heatmap 옆에 병기**하는 방식을 권장

**변수 수가 많을 때 페이지 분할 전략**
1. 02/04(표): 20~25행/페이지로 자동 분할
2. 05(분포): 대표 변수 선정(분산·왜도 상위 또는 접두어 패턴으로 그룹화 후 그룹당 1개 대표) 12~16개 → 3~4페이지 + 나머지 요약 1페이지
3. 08(상관): 변수 많아도 heatmap은 1페이지 유지(축소·재정렬로 대응), 대신 상위 상관쌍 표를 같은 페이지 하단에 추가

**PDF가 지나치게 길어지는 것 방지**
- 전체 페이지 수 상한(가이드값 40페이지) 설정 → 근접 시 "대표 변수만" 모드로 자동 전환하고, 표지에 "OO개 변수 중 대표 N개만 개별 표시, 전체는 AI Context 참고" 안내
- 조건부 실행 자체가 1차 방어선(§4) — 표본 13개 기준 시뮬레이션하면 센서형(`08`,`13`)은 10~12페이지, 품질/불량형(`04`,`37`)은 16~20페이지, 변수 매우 많은 형(`42`)은 18~22페이지 수준으로 예상되어 40페이지 상한에 걸리는 경우는 드물 것으로 판단

**"많이 보여주기 vs 가독성" 균형**: 결론적으로 "모든 변수를 다 보여주는 것"은 포기하고 **"대표 변수 개별 시각화 + 전체 변수 표/미니그리드 요약 + 전체 수치는 AI Context"** 3단 구조로 타협하는 것을 권장한다.

## 6. PDF vs AI Context 구분

**A. PDF에 반드시 보여줘야 하는 것** (사람의 빠른 직관적 판단용)
- 표지/핵심 지표 카드, dtype 구성, 상수/제외 컬럼 요약
- 대표 변수 히스토그램/박스플롯(이미지)
- 상관 heatmap(재정렬본, 이미지)
- PCA 2D 산점도, Cluster Profile(해석 문장 포함)
- Target 클래스 비율 배너 + 그룹 비교 시각화
- Key Observations(관찰 사실 종합)

**B. AI Context에 반드시 저장해야 하는 것** (PDF엔 없거나 요약만 있는 원본 수치)
- 파싱 메타(헤더 행, 인코딩, 원본 컬럼명 vs 자동 생성 컬럼명 매핑)
- 전체 컬럼 프로파일 표(제외 여부 플래그 포함, 전체 행)
- 전체 상관행렬(모든 pair) + Correlation Network용 edge list(threshold 이상 쌍)
- PCA 전체 loading 행렬, 전체 설명분산 벡터
- 군집별 centroid 전체 좌표(모든 변수 기준 z-score)
- 이상치로 판정된 row의 인덱스/실제 값 목록(IQR·IF 각각)
- Association rule 전체 목록(support/confidence/lift) 또는 생략 사유
- target 후보로 제시했던 구조적 후보 리스트(사람이 확정하지 않았다면 "미확정" 상태로)

**C. 둘 다 필요하지만 표현 방법이 달라야 하는 것**
| 항목 | PDF 표현 | AI Context 표현 |
|---|---|---|
| 기술통계 | 대표/전체 표(이미지 아님, 표) | 동일 표를 JSON 배열로(둘 다 표라서 형태 차이는 크지 않음) |
| 분포 | Histogram/Boxplot 이미지 | mean/std/skew/kurtosis/quantile 수치 |
| 상관 | Heatmap 이미지 + Top-N 쌍 텍스트 | 전체 행렬 수치 + 전체 쌍 리스트 |
| 군집 | 2D scatter 이미지 + Cluster Profile 표 | centroid 좌표 + 각 군집의 대표 변수 z-score |
| 이상치 | 비율(%) + boxplot | 이상치 row 인덱스 전체 + 값 |
| 시계열 | 라인차트 이미지 | 구간별 rolling 통계 수치 + 추세 기울기 값 |
| Key Findings | 자연어 문단(사람이 읽기 좋은 톤) | `{flag_type, column, metric, severity}` 구조화 리스트 |

## 7. 최종 설계안

> 아래는 실제 실행 시 "조건 충족 시" 생성되는 최대 구성이다. 각 데이터셋은 §4 규칙에 따라 이 중 일부만 갖는다.

### Part 0. 매니페스트

#### 페이지 0. 표지 & 실행 매니페스트
- 분석 목적: 이 리포트가 어떻게 생성됐는지 투명하게 기록
- 무엇을 확인하는가: 파일명, 실행 시각, 행/열 수, 헤더 행 지정값, 인코딩, 조건부 실행된/생략된 항목 목록과 그 사유
- 왜 필요한가: 실측에서 헤더 없음(`03`,`13`)·2행 헤더(`37`) 사례가 나왔기 때문에, 컬럼명이 원본 그대로인지 자동 생성됐는지를 밝히지 않으면 이후 모든 페이지가 오독될 수 있음
- 데이터 조건: 항상
- 추천 시각화: 없음(텍스트/표)
- 페이지당 시각화 개수: 0
- 추가 설명: 조건부 스킵 항목은 "왜 스킵했는지"까지 한 줄씩
- 주요 해석: 없음(사실 기록)
- FE 연결: 없음
- AI Context 저장값: 파싱 메타 전체, 실행/스킵 항목 리스트+조건값

### Part 1. 데이터 이해

#### 페이지 1. Dataset Overview
- 분석 목적: 데이터 규모·구성 파악
- 확인 내용: 행/열 수, dtype 구성, 중복행, 파일 크기
- 데이터 조건: 항상
- 추천 시각화: 지표 카드 + dtype 막대 1개
- 시각화 개수: 1
- 주요 해석: "행 대비 열이 매우 많다/적다" 등 규모 감각 문장
- FE 연결: 없음
- AI Context: 전체 수치

#### 페이지 2~N. Column Profile
- 목적: 변수별 상태·분석 포함/제외 여부 확정
- 확인 내용: dtype, 결측률, unique/unique비율, constant, ID-like, 샘플값
- 데이터 조건: 항상, 20~25행/페이지 분할
- 시각화: 없음(표)
- 주요 해석: 제외 컬럼 수·사유 요약
- FE 연결: 상수/ID-like 제거 후보
- AI Context: 전체 표 + 원본 컬럼명 매핑

#### 페이지 N+1. Missing Values — *조건부(결측 존재 시)*
- 확인 내용: 결측률 상위, missingness matrix, 공동결측 패턴
- 시각화: 2개
- 주요 해석: 조건부 결측/공동결측 발견 시 원인 추정 문장
- FE 연결: 결측 플래그 파생변수

### Part 2. 데이터 분포

#### Descriptive Statistics
- 확인 내용: count~kurtosis
- 시각화: 표만
- FE 연결: 왜도 큰 변수 변환 후보

#### Numerical Distribution
- 확인 내용: 대표 변수 히스토그램/박스플롯
- 시각화: 4개/페이지, 대표 12~16개 + 요약 그리드 1페이지
- FE 연결: 다봉분포·쏠림 발견 시 이산화/파생 후보

#### Categorical Distribution — *조건부*
- 시각화: Top-N 막대, 4개/페이지

#### Outlier Analysis
- 확인 내용: IQR 비율/박스플롯(항상) + IF 다변량(조건부)
- FE 연결: 클리핑/이상치 플래그

### Part 3. 변수 간 관계

#### Correlation Analysis — *조건부(수치형≥2)*
- 시각화: 재정렬 heatmap 1개 + Top-N 쌍 표
- FE 연결: 다중공선성 제거/그룹 대표값

#### Feature Relationship — *조건부*
- 시각화: 선형 Top-N + 비선형 후보 산점도(LOWESS)
- FE 연결: 교호작용/다항 피처

#### Categorical × Numerical — *조건부*
- 시각화: Boxplot/Violin 2개/페이지
- FE 연결: 그룹 원-핫 인코딩 우선순위

#### Categorical × Categorical — *조건부(usable categorical≥2)*
- 시각화: Crosstab heatmap + Cramér's V

### Part 4. 다변량 구조

#### PCA — *조건부(유효 수치형≥5)*
- 시각화: Scree+2D scatter(1p) + Loading(1p)
- FE 연결: 차원축소 파생/저기여 변수 제거

#### Clustering — *조건부*
- 시각화: 2D scatter+elbow/silhouette(1p, 작게) + Cluster Profile(1p, 핵심)
- 알고리즘: KMeans 고정(실루엣으로 k 선택) — target 불균형을 근거로 알고리즘을 바꾸지 않는다
- FE 연결: 군집 라벨 파생, 판별 변수 우선순위

*(Correlation Network는 PDF 미포함 — §3, §6 참고. AI Context에만 저장)*

### Part 5. 조건부 분석

#### Target Analysis — *조건부(target 제공 시)*
- 타입별 분기: §3 표 참고(binary/multiclass/regression)
- 시각화: 클래스 비율 배너 + 그룹 비교(1~3p, 타입에 따라 가변)
- FE 연결: 판별 변수 우선순위, 불균형 시 평가지표 경고

#### Time Series Analysis — *조건부(datetime_ok 또는 순서 정보)*
- 시각화: 추세+rolling(2p)
- FE 연결: rolling/lag/diff, 드리프트 구간 파생

#### Association Analysis — *조건부(엄격, §4)*
- 시각화: 규칙 Top-10 표(대부분 생략 예상)
- FE 연결: 조합형 파생변수

### Part 6. 종합

#### Key Findings
- 결측/왜도/상관/이상치/군집/target/시계열 발견 사항 규칙 기반 자동 요약(우선순위 상위 10개)

#### Feature Engineering Hints
- 위 발견을 "다음에 검토할 후보" 형태로 재구성(제거/결합/파생/변환 4범주로 그룹화)

### 데이터 유형별 자동 PDF 구성 예시

**1. 일반 공정 데이터** (예: `49_주조_설비_예지보전`, `50_주조_공정최적화` 유형 — target 명확, datetime 있음, 변수 15~25개)
표지 → Overview → Column Profile → Missing → Descriptive Stats → Numerical Distribution → Outlier(IQR+IF) → Correlation → Feature Relationship → Cat×Num(있으면) → PCA → Clustering → Target Analysis(binary) → Time Series → Key Observations (**약 16~18페이지**)

**2. 센서/시계열 데이터** (예: `08_Meltingtank`, `13_회전기계`, `14_공정운영` 유형 — target 없음/애매, 변수 5~10개, 행 매우 많음)
표지 → Overview → Column Profile → Missing → Descriptive Stats → Numerical Distribution → Outlier(IQR만, 변수 적어 IF 조건 미충족 가능) → Correlation(변수≥2면) → Time Series(비중 크게) → Clustering(레짐 발견용, 조건부) → Key Observations — **Categorical/PCA/Association 스킵**(범주형 없음, 변수<5) (**약 9~11페이지**)

**3. 불량/품질 데이터** (예: `04_Molding`, `37_주조_품질보증` 유형 — target 명확·불균형 심함)
표지 → Overview → Column Profile(상수 컬럼 다수 플래그) → Missing(조건부 결측 강조) → Descriptive Stats → Numerical Distribution → Categorical Distribution → Outlier → Correlation → Feature Relationship → Cat×Num → PCA → Clustering → Target Analysis(binary 또는 `37`처럼 multiclass/다중이진, 비중 크게 2~3p) → Key Observations (**약 18~20페이지**)

**4. 범주형 중심 데이터** (예: `20_생산계획`, `19_생산공정`(연관분석용), `22_열처리공급망` 유형 — 소규모, 카디널리티 다양)
표지 → Overview → Column Profile(ID-like 고카디널리티 플래그) → Missing → Descriptive Stats(수치형 적음) → Categorical Distribution(Top-N) → Cat×Cat → Cat×Num → Association(카디널리티 관리되면) → Correlation(수치형≥2면) → Key Observations — **PCA/Clustering/Time Series 대부분 스킵**(조건 미충족) (**약 10~12페이지**)

**5. 변수 수가 매우 많은 데이터** (예: `37`, `42`, `03_CNC` 유형 — 48~58열)
표지 → Overview → Column Profile(다중 페이지, 100%결측/상수 다수 플래그 강조) → Missing(매트릭스+공동결측) → Descriptive Stats(다중 페이지) → Numerical Distribution(대표 12~16개 + 요약 그리드 1p) → Outlier(대표 변수 대상) → Correlation(재정렬 heatmap 1p 크게, network 없음) → PCA(고차원이라 특히 유용) → Clustering → Target/Cat 페이지(해당 시) → Key Observations (**약 18~22페이지**)

## 다음 단계 제안 — 확정된 전제

1. **입력 스펙**: 대회 당일 이 50개 데이터셋 중 **무작위로** 하나가 선택된다. 즉 "전처리가 완료된 CSV"라는 표현이 있어도, 모듈은 이번 검증에서 발견한 모든 구조적 특이 사례(헤더 없음, 2행 헤더, 인코딩 문제, 상수/100%결측 컬럼, 조건부 결측, 고카디널리티 범주형, 컬럼명과 실제 파싱 결과 불일치 등)가 **언제든 나올 수 있다는 전제로 방어적으로 설계한다.** 50개 중 특정 유형만 나올 거라고 가정하고 분기를 단순화하면 안 되며, §4의 조건부 실행 규칙과 00번 매니페스트(헤더/인코딩 자동 감지 로그)는 선택 사항이 아니라 필수 구현 항목이다.
2. **target 지정 방식**: 가이드라인 PDF는 분량이 많고 이미지 자료도 많아 **EDA 모듈(또는 AI 에이전트)이 자동으로 파싱해 target을 넘기는 방식은 채택하지 않는다.** 대신:
   - target은 **사람이 실행 시점에 파라미터로 직접 지정**한다(예: `--target PassOrFail`, 다중 이진 컬럼이면 `--target Defects.0,Defects.1,...`). 지정하지 않으면 모듈은 target 없는 모드로 전체 파이프라인을 실행한다(15번 Target Analysis만 스킵, 나머지는 정상 진행).
   - 사람이 가이드라인 PDF 전체를 정독하지 않고도 빠르게 target을 확정할 수 있도록, **02번 Column Profile의 구조적 target 후보 리스트**(저카디널리티 컬럼, 이름에 Pass/Fail/OK/NG/Status/Result/Defect류 키워드가 포함된 컬럼)를 실행 초반에 먼저 출력하는 것을 권장한다 — 사람은 가이드라인에서 "품질/불량 판정 기준" 섹션만 훑고 이 후보 리스트에서 고르면 되므로, PDF 전체를 읽는 것보다 훨씬 빠르다.
   - 즉 파이프라인은 여전히 **1단계**(EDA 모듈 단독 실행)이며, PDF 파싱 단계는 두지 않는다.
